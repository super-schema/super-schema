- **Policy engine** `src/lib/access/*`: scopes GLOBAL ⊃ TENANT ⊃ DOMAIN ⊃ PRODUCT ⊃ entity, ladder VIEWER < AUTHOR < STEWARD < COMPLIANCE_OFFICER < ADMIN, one action→minimum-role table (`actions.ts`, 52 ids, snapshot-tested), `grantAllowed` (checked exhaustively: 5,625 combinations, no escalation).
- **Data model** migrations `20261025230000_access_control` (+ `rollback.sql`) and `20261026000000_webhook_endpoint_creator_optional`: scoped `user_roles`, `users.disabledAt/lastLoginAt`, invitations, auth tokens, auth events, `audit_log.tenantId`. Verified on PostgreSQL 16 and PGlite. Legacy global non-ADMIN roles become one tenant row per tenant; the migration refuses (changing nothing) on case-duplicate e-mails or duplicate role rows.
- **Principal / guard**: `getPrincipal()` (by user id only, disabled = nobody, one read per request), `authorizeInActiveTenant` (resource in the active tenant AND a covering role; foreign = missing answer), the active tenant must be one the user holds a role in, `/no-access` page for role-less users.
- **Enforcement**: every server action and API route goes through the guard; a syntax-tree scan test (`tests/unit/access/deny-by-default.test.ts`, shrink-only pending lists now empty) fails for any unguarded action or route. API v1: sessions carry real roles, the API key is a service principal (`API_KEY_TENANT_ID`, `API_KEY_ROLE`, default ADMIN), webhooks are platform-admin only and secret-free.
- **Leak fixes found by review**: KD-045 (emission closure refuses when a referenced entity is unreadable) and KD-046 (stored schema versions are redacted at every read boundary; stricter than first ruled).
- **Authentication**: password policy (12–72 bytes, deny-list), DB-backed throttling (`auth_events`, hashes only), single-use SHA-256-stored invitation/reset tokens, `AUTH_REGISTRATION=open|invite|closed` (default `invite`), Auth.js maxAge 12 h, disabled users refused everywhere, constant-time login, uniform answers. Production refuses a missing/short/development session secret (process exits).
- **User management UI** (`/admin`): invite with scope picker, revoke invitation, disable/enable (last global admin protected), one-time reset link, role matrix, real status/last-sign-in; role-aware tabs, server-side gate. No code path deletes a user (audit rows pin them; a scan keeps it so).
- **Providers** (`AUTH_PROVIDERS`, google/github/microsoft-entra-id/okta/keycloak/oidc): pure sign-in policy, user must already exist, no self-signup, linking only with a per-provider flag. **Never run against a real identity provider.** Setup guide `docs/auth.md`.
